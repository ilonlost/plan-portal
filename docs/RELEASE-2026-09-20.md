# Проверка релиза 20.09.2026

Изменения сохраняют планы, справочник и учётные записи. Миграция
`20260920_0017` добавляет индивидуальные разрешения пользователя и переносит
прежнюю видимость разделов в независимые настройки существующих сотрудников.
Администраторы сохраняют полный доступ. «Факт производства» остаётся закрыт
обычным пользователям, пока администратор явно не выдаст доступ.

## Проверено

- Панель дат, верхняя горизонтальная прокрутка и заголовки матрицы закреплены
  последовательно. Вертикальная прокрутка принадлежит странице.
- Дневные карточки не перекрывают колонку линии и комментарии.
- Неделя и три недели содержат ровно 7 и 21 день, включая дни вне горизонта плана.
- Индивидуальные права проверяются API и обновляются в открытых сессиях.
- SMTP без TLS не пытается читать CA-файл; обязательный STARTTLS не откатывается
  на незащищённое подключение при ошибке. Диагностика SMTP не отправляет письма.
- Ошибочная или частичная отправка не показывается как успешная.
- Простои через полночь разделяются по дням; потери не меняют задания.
- `.env` и локальные журналы исключены из Docker build context.

## Настройка внешних систем

Для почты выбран тот же режим, который сохранён в ART Portal на VPS:
`smtp.agrohold.ru:25`, без TLS и без SMTP-авторизации. Адрес отправителя
Plan Portal остаётся собственным. Режим можно изменить в администрировании.
Проверка соединения не подтверждает фактическое поступление письма в ящик.

Для реальных простоев нужны `DOWNTIME_DATABASE_URL` и `DOWNTIME_QUERY`.
Запрос должен возвращать `line_code`, `start_at`, `end_at`, `downtime_type`
(`partial`/`full`) и `reason`, поддерживать параметры `:start_at`/`:end_at`.
`line_code` сопоставляется с кодом линии портала или CSB. Время без часового
пояса трактуется как московское; пустое окончание означает текущий момент.
Учётная запись внешней БД должна иметь права только на чтение.

На момент проверки подключение простоев на VPS не заполнено. В доступных
исходных скриншотах №6–7 показаны линии плана, без имени сервера, БД и таблицы.
Интерфейс явно сообщает об отсутствии подключения; реальные события не подменяются
тестовыми. Отчёт «Факт производства» по-прежнему использует обозначенную заглушку ERP.
