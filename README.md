# Производственный план ФК

Самостоятельный портал производственного планирования ПЦ / КЦ. Интерфейс открывается на `http://127.0.0.1:18095/`.

## Что реализовано

- общий план как матрица «цех → линия → дата» с загрузкой, ОХЛ, ЗАМ и свободными часами;
- отдельное открытие каждого цеха и каждой линии;
- справочник SKU, скоростей, квантов замеса, минимальных партий, коробов, ограничений, старых мощностей в штуках и состава рецептур;
- приоритетный расчёт: сначала ОХЛ на фиксированные даты, затем ЗАМ в остаточную мощность;
- для сэндвичей и бургеров с авансовой маркировкой: дата производства ДП = дата маркировки ДМ − 1 день;
- явные конфликты при нехватке мощности и явные свободные часы, если ЗАМ не хватает до 100% загрузки;
- дневные и ночные смены, кванты коробов и замесов;
- ручное изменение даты, смены, линии и объёма планером;
- статусы исполнения и неотгрузки с обязательной причиной и записью в аудит;
- роли `planner`, `master`, `viewer`, проверяемые backend, а не только интерфейсом;
- загрузка `.xlsx` / `.xlsm`, предварительная проверка строк, журнал источников и выгрузка плана в Excel.

## Поддержанные книги

1. `Недельный план ФК 33-34-35w 2026 (10.08.26).xlsx`
   - лист `ОХЛ`;
   - исходные значения в штуках переводятся в кг;
   - квант короба получается из наименования;
   - дата ОХЛ не переносится.
2. `ПЛАН_КВАРТАЛ ФК август-сент-окт (корр.11.08.26).xlsx`
   - лист `План ЗАМ+Напитки`;
   - значения в кг;
   - ЗАМ распределяется внутри недели после ОХЛ.
3. `План производства 12.08.2026.xlsm`
   - актуальный `Справочник`, часы работы и структура исходных листов `ПЦ`, `КЦ 1`, `КЦ 2`; в портале оба листа КЦ объединяются в единый цех `КЦ`;
   - скорости, замесы, минимальные партии и ограничения.
4. `План производства 2026.xlsx`
   - старые кванты и мощности в штуках;
   - лист `Рецептура 50` используется для числа компонентов по готовому SKU.

Последние версии одного и того же файла заменяют его роль в расчёте. ОХЛ и ЗАМ объединяются в один активный комплексный план.

## Иерархия производства

- ПЦ: Булка, Слойка, Хлеба, Ручная зона ПЦ, Сухари.
- КЦ: Сэндвичи, Жареные блюда, Лазанья, Миквак, Бургеры, Супы, Салаты, Напитки, Ручная зона КЦ.

## Запуск

Требуются Docker Desktop / Docker Engine и Docker Compose.

```bash
docker compose up -d --build
```

Файл `.env` для локального запуска не обязателен. Значения по умолчанию изолированы внутри этого проекта. Для общего сервера задайте собственный `POSTGRES_PASSWORD`.

```bash
docker compose ps
docker compose logs -f ppp-backend
```

- Портал: `http://127.0.0.1:18095/`
- OpenAPI: `http://127.0.0.1:18095/api/docs`

Остановка без удаления базы:

```bash
docker compose down
```

Не используйте `docker compose down -v`, если нужно сохранить импортированные планы.

## Роли

Для локальной демонстрации пользователь выбирается в нижней части бокового меню.

- `demo.planner` — полный доступ к плану, импорту и справочнику;
- `master.sandwich` — просмотр только линии «Сэндвичи», изменение только статуса исполнения;
- `master.sloyka` — просмотр только линии «Слойка», изменение только статуса исполнения;
- `viewer` — только просмотр.

Портал использует подписанную HTTP-only сессию. В локальном режиме доступны учётные записи `demo.admin / demo`, `demo.planner / demo`, `master.sandwich / demo`, `master.sloyka / demo`, `viewer / demo`. Для корпоративного контура установите `AUTH_MODE=ldap` и заполните LDAP-группы в `.env`; роли администратора, планера, мастера и просмотра назначаются по группам AD.

Почтовые уведомления включаются через `EMAIL_ENABLED=true`, SMTP-параметры и `NOTIFICATION_EMAILS`. Все попытки доставки сохраняются в журнале. Кнопка «Передать завтра в CSB» пока формирует и аудирует тестовый пакет без внешней отправки (`CSB_TEST_MODE=true`).

## Архитектура

```text
React + TypeScript + Vite
          ↓ REST /api
FastAPI → PlanService → PlanningEngine
          ↓
SQLAlchemy + PostgreSQL 16
```

Миграции Alembic и начальная структура 14 реальных линий применяются при старте backend. Исходные Excel-файлы не входят в Git: загрузите их через раздел «Загрузка Excel» в порядке «старый справочник → актуальный справочник → ОХЛ → ЗАМ».

Интеграции NAV/CSB оставлены за отдельными адаптерами: портал уже рассчитывает план и хранит справочник/источники, но отправку заявок во внешние системы нельзя включать без их API, учётных данных и согласованной схемы обмена.
